# doh-finder

Каталог публичных DNS-over-HTTPS резолверов из
[DNSCrypt/dnscrypt-resolvers](https://github.com/DNSCrypt/dnscrypt-resolvers).

Утилита обновляет каталог, проверяет серверы и перебирает их с применением
DNS-over-HTTPS в Windows и сохранением прогресса.
Наличие сервера в каталоге означает, что он опубликован в источнике как DoH-сервис.
Результаты реальных проверок сохраняются отдельно от списка.

Приложение использует **только IPv4**. Записи с IPv6-адресом подключения или
IPv6-литералом в DoH URL исключаются. У сервиса с адресами обеих версий остаются
IPv4-записи. IPv6-адреса из `bootstrapDns` также удаляются.

Записи без явно указанного IPv4-адреса исключаются: в готовом JSON нет
`ip: null`. Адреса через системный DNS при импорте не подставляются.
Проверяющий модуль подключается к DNS-серверам по IPv4 из каталога,
без системного разрешения имени DoH-сервера и без отката на IPv6.

## Запуск

Нужен **Go 1.27.1** — последняя стабильная версия на момент создания проекта,
15 сентября 2026 года. Версия закреплена в `go.mod`. Go с поддержкой
автоматического выбора toolchain скачает её при первом запуске, если необходимо.

Соберите из корня проекта и откройте `.exe`:

```powershell
go build -o bin/doh-finder.exe ./cmd/doh-finder
Start-Process .\bin\doh-finder.exe
```

В `.exe` встроен манифест `requireAdministrator`: Windows запрашивает повышение
прав при обычном запуске и не запускает приложение при отказе. Весь `.exe`,
включая пункты 1 и 2, работает от администратора. Из уже повышенной консоли
можно запускать `.exe` напрямую или использовать `go run` / `make run`.

Откроется консольное меню (также при запуске собранного `.exe` двойным щелчком):

```text
DOH FINDER

1. Update Server List
2. Check Servers
3. Auto Browse
4. Full Cycle
0. Exit

Select an option:
```

Введите `1` и нажмите Enter, чтобы обновить список. Каждый пункт открывается
на очищенном экране. После обновления или проверки нажмите Enter, чтобы
вернуться в главное меню. Введите `0` для выхода; Ctrl+C тоже завершает
программу. Введите `2` для проверки списка, `3` — для автоперебора,
`4` — чтобы подряд обновить список, проверить серверы и перебрать их.
При открытии меню загрузка из интернета не выполняется.

Пункт **Update Server List** получает текущий commit ветки `master`, загружает
`v3/public-resolvers.md` по неизменяемому URL этого commit и сохраняет
`configs/servers.json`. Системные настройки DNS не меняются.
Доступ к GitHub API и raw.githubusercontent.com необходим.

Для обновления без меню используйте `-update`. Например, импорт конкретной
ревизии, уже записанной в каталоге:

```powershell
go run ./cmd/doh-finder -update -ref ccc77405d339da1222773d2fdcf771e2a2e07bbb
```

Флаги:

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `-output` | `configs/servers.json` | Путь к JSON, относительно текущей папки |
| `-ref` | `master` | Последний commit или полный SHA из 40 символов |
| `-timeout` | `1m` | Таймаут каждого обновления; ожидание в меню не ограничено |
| `-update` | `false` | Обновить один раз и выйти, без меню |
| `-check` | `false` | Проверить список один раз и выйти, без меню |
| `--browse` | `false` | Пункт 3 без меню: применить первый рабочий DNS из отчёта |
| `--full-cycle` | `false` | Пункт 4 без меню: обновить, проверить и применить первый рабочий DNS |
| `--priorities` | `no-filter,no-log,dnssec` | Порядок признаков, через запятую |
| `--continue` | `false` | Продолжить после последнего подтверждённого сервера |
| `--start-over` | `false` | Создать очередь с начала; это также поведение по умолчанию |
| `-workers` | `20` | Число параллельно проверяемых серверов, от 1 до 128 |
| `-check-timeout` | `5s` | Таймаут TCP-соединения и каждого DNS-запроса |
| `-report` | `reports/check-results.json` | Путь к отчёту проверки |
| `-state` | `state/browse.json` | Очередь, подтверждённый сервер и снимок для восстановления |
| `-h` | — | Справка |

Режим `-ref <SHA>` не обращается к GitHub API. Это также позволяет повторить
импорт при исчерпании анонимного лимита API. Ошибки сети или повреждённые данные
в режиме `-update` завершают команду с ненулевым кодом, а в меню показывают
ошибку и позволяют повторить попытку. Прежний каталог сохраняется. Для записи сначала
готовится временный файл рядом с каталогом, затем готовый файл заменяет прежний.

## Проверка серверов — пункт 2

Проверка читает готовый `configs/servers.json` и не обращается к GitHub.
Если списка нет или JSON повреждён, выводится ошибка и можно выбрать пункт 1.
Проверяются только записи с явным IPv4; некорректные записи получают
`INVALID_CONFIG` без сетевых запросов.

Для каждого сервера выполняются:

1. TCP-соединение с IP из каталога на порт из DoH URL (по умолчанию 443).
2. Настоящие DNS-over-HTTPS запросы типа A для `example.com` и `iana.org`.
   Используется `AdguardTeam/dnsproxy/upstream` с единственным IPv4-адресом
   в `StaticResolver`. HTTPS-имя сохраняется для SNI и проверки сертификата;
   проверяются и хеши TBS-сертификатов, если они есть в каталоге.
3. Проверка соответствия DNS-ответа запросу, кода ответа и наличия IPv4
   для запрошенного имени с учётом CNAME. Пустые ответы, адреса 0.0.0.0/loopback,
   `SERVFAIL`, `NXDOMAIN` и `REFUSED` не считаются успехом.

TCP и DoH проверяются независимо и параллельно; два DNS-запроса одного сервера
выполняются последовательно. Пул горутин ограничен `-workers`. Один поток
собирает результаты и выводит прогресс, поэтому строки не перемешиваются.

В консоли видны признаки `NoFilter`, `NoLog`, `DNSSEC`, отдельные статусы
и задержки, при ошибке — её текст. Признаки взяты из источника и не проверяются.
JSON-отчёт содержит в `results` **только успешно прошедшие проверку серверы**:
их IP, DoH URL, `properties`, задержки TCP и каждого DoH-запроса в `elapsedMs`,
ответы A, TLS-версию и согласованный HTTP-протокол. `success: true` означает
успешный TCP-тест и оба DNS-запроса. Поля `checked` и `failed` содержат общее
число проверенных и неуспешных записей. Также сохраняются параметры проверки
и время запуска/завершения. Если никто не прошёл, `results` будет пустым массивом
`[]`, заменяющим предыдущие результаты. Порядок успешных записей соответствует
каталогу, независимо от порядка завершения горутин. Исходный каталог остаётся
полным: при следующем запуске снова проверяются все его серверы.

Пример запуска без меню:

```powershell
.\bin\doh-finder.exe -check -workers 20 -check-timeout 5s
```

`-update` и `-check` нельзя объединять. Отчёт не может иметь тот же путь,
что и каталог. Прерванная проверка не заменяет предыдущий полный отчёт.
У `upstream.Exchange` нет аргумента `context`, поэтому после Ctrl+C текущий
DoH-запрос может завершаться до истечения своего таймаута; новые запросы не
запускаются. В режиме `-check` код 0 означает завершённую проверку и сохранённый
отчёт, даже если часть серверов недоступна. Ошибка загрузки/записи даёт код 1.

Это проверка TCP и DoH, а не ICMP ping, обычного DNS/53 или загрузки сайтов.
Успешный DoH-ответ не гарантирует доступность произвольного сайта. Никакие
настройки DNS Windows не изменяются. HTTP/3 не используется; доступны HTTP/1.1
и HTTP/2. Текущий клиент AdGuard заменяет query-параметры URL, поэтому такие
URL явно отклоняются с `INVALID_CONFIG`, чтобы не проверять другой endpoint.
Если в URL указан IP-литерал, отличающийся от `ip` в каталоге, запись также
получает `INVALID_CONFIG`: библиотека для таких URL игнорирует `StaticResolver`.
Это ограничение клиента, а не результат измерения доступности сервера.

## Автоперебор — пункт 3

Требуется **Windows x64 с поддержкой штатного DoH**. Права администратора
запрашиваются автоматически при запуске `.exe` благодаря встроенному манифесту.
Одновременно может быть открыто только одно меню утилиты.

1. Выберите порядок признаков: `1. NoFilter`, `2. NoLog`, `3. DNSSEC`.
   Введите перестановку, например `1 2 3` или `3 2 1`; пустой Enter означает
   `1 2 3`. Приоритеты не исключают серверы: сначала сравнивается первый
   признак, затем второй и третий. При одинаковых признаках сортируем по
   среднему времени успешных DoH-запросов из пункта 2, от меньшего к большему.
2. Если состояние уже сохранено, появятся `1. Start over`, `2. Continue`.
   При первом запуске этот вопрос пропускается. Продолжение использует
   сохранённую очередь и её приоритеты; новый порядок действует при старте заново.
3. Утилита автоматически перебирает кандидатов до первого прошедшего проверку.
   Выбирается подключённый IPv4-адаптер с наименьшей суммарной метрикой маршрута
   по умолчанию. Его имя показывается при применении. В очереди нет повторений
   пары IPv4 + DoH URL. Результаты неуспешных проверок из пункта 2 не используются.
4. Перед каждой попыткой на диск записывается снимок текущих IPv4 DNS и
   свойств DoH адаптера, включая автоматическое получение DNS. Затем применяется
   **один** кандидат: явный DoH URL, шифрование обязательно, откат на UDP/TCP
   выключен. Резервного DNS во время проверки нет.
5. Настройки перечитываются из Windows. Через `DnsQueryEx` на выбранном адаптере
   проверяются A-записи `example.com` и `www.iana.org`, без кэша, hosts и LLMNR.
   Затем выполняются HTTPS GET этих сайтов по полученным IPv4, с проверкой TLS,
   без прокси и перенаправлений. На каждый DNS-запрос и сайт отводится до 15 секунд.
   DNS-запрос исполняется в дочернем процессе, который завершается при таймауте.
6. При успехе показывается текущий сервер. Можно открыть браузер и проверить
   свои сайты, пока экран ожидает ответа. `1. Try next server` продолжает;
   `2. Keep this server` **подтверждает** выбор. Только после подтверждения
   предыдущий подтверждённый сервер добавляется вторым, также с обязательным DoH.
   Новый сервер становится последним рабочим. При первом подтверждении резервного
   ещё нет; если IP совпадает, дублирующий резервный не добавляется.
7. `0. Back` или Ctrl+C до подтверждения восстанавливают прежние настройки.
   При неудаче кандидата настройки восстанавливаются до перехода к следующему.
   Если никто не подошёл, остаются настройки до перебора. Подтверждённая пара
   остаётся активной после закрытия утилиты.

`state/browse.json` сохраняет снимок очереди, позицию и последний подтверждённый
сервер. Обновление каталога или отчёта не меняет текущую очередь. Продолжение
начинается со следующего кандидата после последней попытки. Перед изменением
Windows сначала сохраняется журнал восстановления; если запись не удалась,
сеть не меняется. При аварийном завершении восстановление выполняется при
следующем запуске меню с правами администратора. Если восстановление не удалось,
перебор останавливается и журнал сохраняется для повторной попытки.

IPv6-настройки не меняются. Если у выбранного адаптера есть действующие IPv6 DNS,
активная NRPT-политика или неподдерживаемые настройки DNS профиля, автоперебор
останавливается с объяснением. Проверка контрольных сайтов не гарантирует
доступность всех сайтов; браузер со своим DoH может использовать другой DNS.

Настройка использует документированный
[SetInterfaceDnsSettings](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-setinterfacednssettings)
и [свойства DoH адаптера](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-dns_doh_server_settings).
Штатный PowerShell используется только для чтения маршрутов и сведений об адаптере.

## Полный цикл — пункт 4 и флаги

Пункт `4. Full Cycle` последовательно выполняет пункты 1 и 2, затем открывает
перебор из пункта 3. В меню после системной проверки можно открыть браузер,
проверить нужные сайты и выбрать «Следующий» либо «Остановиться на этом».
При уже сохранённой сессии выбор «Продолжить» использует **новый** отчёт
проверки и начинает после последнего подтверждённого сервера.

Для запуска без меню из консоли администратора:

```powershell
.\bin\doh-finder.exe --update
.\bin\doh-finder.exe --check
.\bin\doh-finder.exe --browse --priorities no-filter,no-log,dnssec
.\bin\doh-finder.exe --full-cycle --priorities no-filter,no-log,dnssec
.\bin\doh-finder.exe --full-cycle --continue --priorities dnssec,no-filter,no-log
```

Каждая команда работает без ввода. `--full-cycle` обновляет каталог из GitHub,
заново проверяет доступность всех IPv4 DoH-серверов и перебирает прошедшие,
пока один не пройдёт проверку через DNS-клиент Windows и контрольные сайты.
**Успех команды означает подтверждение выбора**: новый DNS остаётся основным,
предыдущий подтверждённый рабочий DNS добавляется резервным с обязательным DoH.
При ошибке или Ctrl+C незавершённая попытка откатывается. Команда возвращает
код 0 после подтверждения и ненулевой код при ошибке или исчерпании очереди.

`--priorities` принимает все три имени `no-filter`, `no-log`, `dnssec` ровно
по одному разу, в нужном порядке. Без флага используется прежний порядок
`1 2 3`. В меню можно по-прежнему ввести цифры, а Enter выбирает порядок
из `--priorities`.

`--browse --continue` использует сохранённую очередь и начинает **после**
последнего подтверждённого сервера. `--full-cycle --continue` строит очередь
по свежему отчёту и ищет этот сервер по паре IPv4 + DoH URL. Если его там уже
нет, команда сообщает об этом и не применяет новый DNS. `--start-over` явно
начинает с начала; его нельзя сочетать с `--continue`. Флаги `--continue` и
`--start-over` доступны только вместе с `--browse` или `--full-cycle`.
Одновременно можно выбрать только один из режимов `--update`, `--check`,
`--browse`, `--full-cycle`. Параметры путей и таймаутов из таблицы выше
действуют и в полном цикле.

## Формат каталога

Верхний уровень содержит `schemaVersion`, `source` и массив `resolvers`.
В `source` записаны репозиторий, SHA commit, URL исходного файла, SHA-256 его
байтов и время импорта UTC. Контрольная сумма служит для идентификации данных;
подпись Minisign в текущей реализации не проверяется.

Каждая запись соответствует **одному DNS stamp**, а не одному оператору:

```json
{
  "name": "a-and-a",
  "ip": "217.169.20.22",
  "dohUrl": "https://dns.aa.net.uk/dns-query",
  "stamp": "sdns://AgcAAAAAAAAADTIxNy4xNjkuMjAuMjIADWRucy5hYS5uZXQudWsKL2Rucy1xdWVyeQ",
  "properties": {
    "dnssec": true,
    "noLog": true,
    "noFilter": true
  },
  "certificateHashes": [],
  "bootstrapDns": []
}
```

- `ip` — адрес подключения к DoH-сервису из stamp, а не обещание поддержки DNS
  на порту 53. Обязательное поле с IPv4-адресом из источника. Записи с IPv6
  или отсутствующим IP исключаются из каталога.
- `dohUrl` — полный HTTPS URL с исходными именем, портом, путём и параметрами.
  Имя из URL нужно сохранять при проверке TLS, даже подключаясь к `ip`.
- `name` — имя секции источника. Оно может повторяться: у сервиса бывает
  несколько адресов. Все прошедшие IPv4-фильтр stamps сохраняются отдельно.
- `properties` — заявленные в источнике свойства; приложение их не проверяет.
  Каталог включает прошедшие IPv4-фильтр DoH-записи, в том числе фильтрующие сервисы.
- `certificateHashes` — SHA-256 хеши TBS-сертификатов из stamp в hex.
- `bootstrapDns` — рекомендованные обычные DNS-резолверы для разрешения имени
  DoH-сервиса; это **не дополнительные IP самого DoH-сервиса**.
- `stamp` — исходные параметры подключения в формате
  [DNS Stamps](https://dnscrypt.info/stamps-specifications/).
  Сохраняется без изменений для связи с источником, поэтому внутри исходного
  stamp могут остаться IPv6 bootstrap-адреса. Сетевой адаптер использует
  поля `ip`, `dohUrl` и `certificateHashes`; исходный stamp и bootstrap-адреса
  не передаются клиенту и не могут включить IPv6.

Отбор выполняется по идентификатору протокола `0x02`, а не по имени.
DNSCrypt, DoT, DoQ, ODoH и relays не включаются. Используется именно публичный
список `v3/public-resolvers.md`; отдельные списки проекта не объединяются.
Записи упорядочены по имени и stamp для удобства просмотра изменений.

Для обновления выберите пункт `1` в меню или запустите с `-update`. Ручные правки генерируемого
`configs/servers.json` будут заменены при следующем успешном импорте.

## Сборка и проверки

```powershell
go test ./...
go vet ./...
go build -o bin/doh-finder.exe ./cmd/doh-finder
.\bin\doh-finder.exe -h
.\bin\doh-finder.exe
```

При наличии `configs/servers.json` в текущей папке используются данные оттуда.
Иначе данные ищутся рядом с `.exe` (для `.exe` в `bin` — в родительской папке),
чтобы запуск от администратора не зависел от рабочей папки Windows.
Явные относительные пути флагов отсчитываются от текущей рабочей папки.
Собранный `.exe` работает без установленного Go.

Манифест находится в `cmd/doh-finder/app.manifest`; готовый ресурс
`rsrc_windows_amd64.syso` хранится рядом с ним в репозитории и автоматически
включается обычным `go build`. После изменения манифеста выполните
`go generate ./cmd/doh-finder` (или `make resources`), затем пересоберите `.exe`.
Генератор `akavel/rsrc` закреплён на версии `v0.10.2` и нужен только для генерации
ресурса. Уровень запуска описан в
[документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests).

Тесты работают локально через `httptest` и временные каталоги, без запросов
к публичным DNS-серверам. Проверяются разбор и исключение IPv6, сохранение IPv4,
несколько stamps под одним
именем, отсутствующие IP, нестандартные порты, хеши сертификатов, bootstrap DNS,
ошибки загрузки/разбора и сохранность каталога при сбое.
Проверки DoH тестируются на локальном TLS-сервере: привязка к IPv4 с правильным
SNI, сертификаты, хеши, DNS-коды ошибок, CNAME, HTTP-ошибки и таймауты.
Для пула проверяются реальная параллельность, лимит горутин, порядок отчёта
и отмена. Консольные тесты покрывают пункт 2 и возврат в меню после ошибки.
Для автоперебора проверяются приоритеты, порядок по задержке, сохранённая очередь,
подтверждение резервного DNS, изоляция кандидата, откат при отказах и отмене,
восстановление после перезапуска и ошибки записи. Тесты переключения используют
подмену системного адаптера и не меняют DNS компьютера.

Нативный тест чтения можно включить через `DOH_FINDER_READ_TEST=1`.
Тест `TestNativeApplyAndRestore` выполняется только при отдельном
`DOH_FINDER_LIVE_TEST=1`, с правами администратора и абсолютным путём
`DOH_FINDER_LIVE_JOURNAL` для аварийного восстановления. Он временно применяет
существующий основной DNS без резервного, проверяет DNS/HTTPS и восстанавливает
исходные настройки. Если процесс был аварийно завершён, восстановление доступно
через запуск приложения с `-state <путь к этому журналу>`.

Также доступны `make build`, `make run`, `make test`, `make lint`
(если установлен Make; `lint` запускает `go vet`).

## Архитектура

См. [docs/architecture_guidelines.md](docs/architecture_guidelines.md).
Сборка зависимостей выполняется обычными конструкторами, логирование — через
`log/slog`. Uber Fx и Zap не используются.

Основные внешние зависимости:

- [go-dnsstamps](https://github.com/jedisct1/go-dnsstamps) — разбор списка.
- [AdGuard dnsproxy/upstream](https://pkg.go.dev/github.com/AdguardTeam/dnsproxy/upstream) — DoH-клиент.
- [miekg/dns](https://github.com/miekg/dns) — DNS-сообщения.
